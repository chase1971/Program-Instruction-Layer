Capture Ladder — Quick Reference

Each rung: what you say · what it means · what happens · cost & limits. Token numbers are rough guesses (~15–25 tokens per line of rule text).

Two kinds of cost — don’t mix them up.
KindWhat it meansWho feels it
Token cost Rule/doc text loaded into every chat (rung 4 worst; rung 5 only when opened) Every future session — context gets crowded, agent skims
Work cost Wrong rung → agent builds the wrong thing, or you maintain code/hooks that don’t solve the problem This session — and every time someone touches that code later

“Zero token cost” on rung 1–2 only means the second row isn’t a per-chat tax. It does not mean “put anything here for free.” Wrong rung still burns your session and adds complexity.

  • Rung 1 wrong → agent builds code/infrastructure for an AI habit problem. Session eaten by engineering; app gets heavier for no reason.
  • Rung 4 wrong → you pay tokens every chat forever for something you do monthly.
  • Rung 5 wrong → agent never finds the doc; you repeat yourself anyway.

C:\ link example: Chat links are what the AI types in Cursor — Macro App code can’t block that. Rung 1 would mean inventing a whole tool for a behavior note. Rung 3+5 fixes it in ~8 lines + an exemplar. Same outcome, fraction of the work — that’s why “overkill” matters even at “zero token cost.”

Pick a rung in one question: “Would I need this if I’m only fixing Pearson homework and never touch the toolbar?”
  • No → rung 3, 5, or AGENTS note — not rung 4
  • Yes, every app, every chat → rung 4 (rare)
  • The app itself keeps breaking because two places do the same thing → rung 1
  • Agents keep committing bad stuff → rung 2
  • Just this course / task, write it down → rung 5

Rung 1 — Fix the program so the wrong way can’t happen

Strongest. The app itself blocks the mistake — not a note to the AI.

Good for rung 1

  • Two parts of your app both save the same setting and fight each other
  • Agents keep adding a second way to do X and bugs follow
  • Wrong action would cause data loss or corruption if it happened

Don’t use rung 1 for

Don’t sayWhy notSay this instead
“Make it impossible to give me a C:\ link in chat.” That’s AI behavior in Cursor — not something Macro App code controls. Agent may waste the session building a tool that doesn’t touch chat. → “Capture that, not always-on: when I say link it, give http 8765, never C:\.” (rung 3+AGENTS)
“Remember how Pearson menus work.” That’s knowledge, not app architecture. → “Capture in the Pearson doc.” (rung 5)
“Every chat should pull git first.” Habit for the AI, not a code constraint. → “Every session pull git…” (rung 4)
What you’d sayWhat you’re asking forWhat the agent does
“Capture that: only one place in Macro App saves my display settings.” No second save path that overwrites prefs. (Code change — one module owns saves.) Rewires the app so all saves go through the same door. Next agent can’t add a stray save without noticing.

Cost & capacity (rung 1)

Chat token cost
~zero ongoing — no rule text loaded every session. You pay once in code size.
How many before “too much”
Many separate fixes OK — each is normal app maintenance, not context bloat.
Thousands of these?
Doesn’t clog AI context. Agent doesn’t “scan” them — the running program enforces behavior.
When it goes wrong
Big refactors; agent breaks something else. Wrong rung cost: whole session spent building code you didn’t need — not token bloat.

Rung 2 — Automatic gatekeeper when pushing to GitHub

Robot check on commit/push — rejects bad changes before they stick.

Good for rung 2

  • Same mistake keeps getting committed to GitHub (huge files, broken doc links)
  • You want a robot “stop sign” at push time — not another reminder in chat
  • The violation is checkable in files (“over 800 lines”, “dead link in docs”)

Don’t use rung 2 for

Don’t sayWhy notSay this instead
“Block C:\ links in chat on commit.” Chat isn’t committed unless you save it. Hook won’t catch live conversation. → AGENTS note: “link it = http 8765” (rung 3/AGENTS)
“Never launch Macro App without asking.” Can’t auto-detect “agent launched GUI” in a file diff. → “Every session never open windows…” (rung 4)
What you’d sayWhat you’re asking forWhat the agent does
“Capture that: block the commit if a file is over 800 lines.” Pre-commit / CI check, not a chat reminder. (check-file-size.js) Adds automatic checker; push stops and explains why until fixed.
“When we wrap session, fail if instruction docs have broken links.” Strict check-docs on end-of-session. (check-docs.js --strict) Push blocked until dead links fixed or you override.

Cost & capacity (rung 2)

Chat token cost
~zero per chat — runs at commit time, not in every conversation.
How many before “too much”
Many checks OK if they’re fast. Too many slow hooks = annoying waits on every push.
Thousands of checks?
Still no chat scan. CI gets slow — that’s the limit, not AI confusion.
When it goes wrong
Agent never commits → check never runs. Wrong rung cost: you thought you were protected but nothing actually gates the behavior.

Rung 3 — Reminder when working in that app (Macro App, Pearson, HTML…)

Not every chat — only when files for that app are in play, or you ask.

Good for rung 3

  • Rule is for one app or area (Macro App Pearson, HTML pages, modals)
  • You do it sometimes — not every task across all apps
  • You said “not always-on” or mean to

Don’t use rung 3 for

Don’t sayWhy notSay this instead
“Every chat: pull git first.” Applies to D2L, toolbar, Pearson — everything. → “Every session pull git…” (rung 4)
“Write a 200-line Pearson encyclopedia.” Big reference belongs in a doc, not a rule file. → “Capture in Pearson doc, task index only in rule.” (rung 5 + thin rung 3)
“Only one module may save settings.” That’s app code, not an AI reminder. → “Only one place in Macro App saves…” (rung 1)
What you’d sayWhat you’re asking forWhat the agent does
“Capture that, not always-on: in Macro App Pearson, read the browser doc first.” App rule file for Pearson folders. (pearson-browser-automation.mdc) Writes ~40-line rule. Pearson work → agent sees it. D2L/toolbar work → zero cost.
“HTML link rule — don’t put it in always-on.” Remember delivery (8765 http) without taxing every chat. (html-infographic-delivery.mdc) Glob rule + short AGENTS note. New chat + “link it” → agent knows pattern.

Cost & capacity (rung 3)

Chat token cost
~750–1,250 per rule when it loads — only when matching files or agent reads it.
How many before “too much”
Many files on disk OK. Problem = overlap: 5+ rules all firing on the same file at once (~4k–6k tokens dumped together).
Thousands on disk?
AI does NOT scan all of them. Cursor injects only rules whose file pattern matches what you’re editing. 1,000 Pearson-only rules don’t load during toolbar work.
When it goes wrong
Contradictory rules on same glob; agent skims long stack. Chat-only task (no file open) → rule might not auto-load. Wrong rung cost: token overlap if you duplicated rung 4 content here.

Rung 4 — Every new chat must know this

Always-on rules. Small sacred list — git sync, no surprise windows, PowerShell, etc.

Good for rung 4

  • Applies to every task — git sync, don’t hijack my screens, PowerShell quirks
  • High pain if missed once (conflict, focus stolen, broken terminal commands)
  • Short — a few sentences, not a manual

Don’t use rung 4 for

Don’t sayWhy notSay this instead
“Make a rule for HTML links.” You use HTML occasionally; burns always-on slot every chat forever. → “HTML rule, not always-on” (rung 3) + “link it like exam2-review-map” (rung 5)
“Remember all Pearson click paths.” Pearson-only — huge if always-on. → Pearson doc + rung 3 when in Macro App
“Document how exam2-review-map layout works.” That’s a page to copy, not universal law. → Keep exam2-review-map as exemplar (rung 5)
What you’d sayWhat you’re asking forWhat the agent does
“Every session: pull git before we start, push when we’re done.” Universal two-machine sync. (40-multi-repo-git-push.mdc) Always-on ~23 lines — every agent gets git habit.
“Remember: never open a window on my screen without asking.” Head-mouse safety. (05-never-display-without-permission.mdc) Always-on ~45 lines — no surprise GUI tests.
“Make a rule for HTML links” (no “not always-on”) You wanted middle ground — agent may wrongly put it here. Say “not always-on” → rung 3 instead. HTML was demoted from here 2026-08-01.

Cost & capacity (rung 4)

Chat token cost
~600–1,000 per rule, every chat. Yours now: ~127 lines ≈ 2k–3.2k tokens before you type anything.
How many before “too much”
Budget ~200 lines total (~5–8 rules). At ~300 lines agents start skimming — rules present but not followed reliably.
Thousands always-on?
Never. All load every chat — context fills before your task. Model quotes rules, misses nuance, feels “heavy.”
When it goes wrong
Duplicate guidance in AGENTS + always-on + docs (pay 3×, they disagree). Simple questions get slow. You lose headroom for actual work.

Rung 5 — Write it down or copy a page

Pearson recipes, HTML pages like exam2-review-map. Cheap storage — read when needed.

Good for rung 5

  • Procedure for one program/task (Pearson harvest, homework comparison HTML)
  • You’ll say “like exam2-review-map” or “what’s in the Pearson doc”
  • Course may end — easy to delete or ignore later
  • Default when unsure — cheaper than rung 4

Don’t use rung 5 for

Don’t sayWhy notSay this instead
“Write in a doc: never use && in PowerShell.” Agents forget to open doc; needs every-session injection. → “Every session PowerShell rule.” (rung 4 — already done)
“Doc only: don’t launch GUI without asking.” Safety-critical — doc alone isn’t reliable enough. → Always-on no-GUI rule (rung 4 — already done)
“Put in a doc: only one code path for saves.” Doc doesn’t stop code — need actual fix. → Rung 1 code change
What you’d sayWhat you’re asking forWhat the agent does
“Capture that in the Pearson doc — how to harvest question IDs.” Recipe in Macro App docs. (PEARSON_BROWSER_AUTOMATION.md) Task Index row + steps. Next time agent reads ~40 lines, runs script.
“Link it like exam2-review-map.” This task: copy that page’s layout + http delivery. Opens exemplar (~300 lines ≈ 2k–4k tokens once), builds new page, gives 8765 link.
“Document Pearson as you go — don’t leave it in chat only.” Session habit + doc update (no “capture” keyword needed). Updates doc before session ends. Same as capture for that flow.

Cost & capacity (rung 5)

Chat token cost
~0 until read then ~400–4k per doc/page opened. Not loaded every session.
How many before “too much”
Unlimited files on disk. Limit is orphans — docs nothing points to = agent never finds them (0% reliability).
Thousands of docs?
No full scan. Agent greps or follows Task Index / “like exam2-review-map.” Risk: wrong doc picked if names overlap; not “read all 1000.”
When it goes wrong
Agent doesn’t know doc exists; reinvents from scratch. Stale doc after Pearson edited. Huge encyclopedia nobody indexes.

Parallel — AGENTS.md short note (not a rung number)

~8 lines in the master AGENTS file — loads every chat like a mini always-on, but cheaper than a whole rule file.

Good for AGENTS note

  • One sentence the agent needs in chat-only tasks (no file open → rung 3 glob might not load)
  • Pointer to an exemplar or doc (“link it like exam2-review-map”)
  • You said “AGENTS note only, not always-on”

Don’t use AGENTS for

Don’t sayWhy notSay this instead
“Put the whole Pearson procedure in AGENTS.” AGENTS loads every chat — you’d pay 4k+ tokens for course-specific steps forever. → Pearson doc (rung 5) + one-line pointer in AGENTS
“Add another always-on rule but put it in AGENTS instead.” AGENTS is always-on — same slot problem as rung 4, often worse (whole file loads). → Rung 3 glob if app-specific; rung 4 only if truly universal and short
What you’d sayWhat you’re asking forWhat the agent does
“Capture that — AGENTS note only, not always-on: when I say link it, use http 8765.” Cross-chat memory without burning a rung-4 slot. Adds ~8 lines to AGENTS.md. Every new chat sees “link it” → http pattern.

Cost & capacity

Chat token cost
Whole AGENTS.md ~370 lines ≈ 4k–8k every chat. Each pointer you add ≈ +120–200 tokens.
How many pointers
Many short pointers OK. At ~500+ total lines AGENTS becomes noise — pointers get lost in prose.
Watch this
Often bigger cost than all always-on .mdc combined. Trim to index + pointers; move recipes to rung 5 docs.
Periodic cleanup (rung 5 — not every chat)
  • Robot (any time): end-of-session node scripts/check-docs.js — dead links, orphans, identical dupes
  • AI judgment (every few months): describe it — e.g. “find the instruction layer audit doc and run it” (rung 5; lives in Programs/docs/)
  • Session metrics — running HTML log (Chase only): http://127.0.0.1:8765/session-scorecards-log.html — agents append via script, never read
  • Robot cannot catch contradictory overlay/modal/HTML guidance — that’s the audit doc’s job
