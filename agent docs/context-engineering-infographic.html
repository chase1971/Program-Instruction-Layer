Instruction layers (strongest → read-on-demand)

1 · Code / lint / tests Cannot misuse — ESLint, file-size check, typed APIs. Hardest for AI to ignore.
2 · Capture skill .claude/skills/capture/SKILL.md — runs when you say trigger phrases; picks the rung and writes the rule.
3 · Always-on AGENTS.md One file at Programs root (~197 non-blank lines). Doc routing, screen safety, PowerShell, git sync, session flow, capture ladder…
4 · Routed docs agent docs/INDEX.md keyword rows → the one owner: an app's AGENTS.md, recipes/INDEX.md, or rules/*.md.
5 · On-demand docs agent docs/recipes/, app docs/*.md, task indexes — read when the task matches, not every turn.
6 · Chat memory Does not persist. Never rely on “we talked about it last week.”

Capture ladder — where new knowledge goes

When you teach something durable, agents push it as high as it will go and delete weaker copies.

  1. Structurally impossible — one owner, API that can’t be misused
  2. Lint or test — violation fails CI
  3. Recipe + index row — recipes/INDEX.md, or a keyword row in the app's AGENTS.md; default for most UI/code patterns
  4. Always-on rule — only if short and universal; budget ~200 lines total
  5. On-demand doc — deep dives, task recipes (Pearson browser, blank iframe…)

Your phrases — automatic vs failsafe

Usually automatic (no keyword needed)

  • Glob rules when editing matching files
  • Grep before adding (AGENTS.md rule #7)
  • End-of-session protocol → git, SESSIONS.md
  • Pearson: update doc after new browser flow (rule)

Failsafe — say when it must stick

“Capture that: …” — durable rule; runs capture skill
“Remember: …” — same
“That was the third time” / “again” — graduate rule up one rung
“Capture that in the Pearson doc” — workflow recipe, not global rule
Verbose is fine: “As you work, document new Pearson navigation in the proper doc”

Chase vocabulary (your dialect)

Generic English ≠ your implementation. Example: “drag handle” → must map to the dwell/drag row in agent docs/recipes/INDEX.md + exemplar (useDwellAttachDrag, toolbar overlay), not generic HTML drag. Timing values live in dwell_constants.py — never restated in a recipe.

First time an agent guesses wrong: capture once — map phrase → doc → exemplar file. After that, grep + rule/doc handle it.

AI does not auto-register keywords globally unless something is written to the repo.

Avoiding rule overload

Do

  • Prefer a recipe + index row over always-on
  • Prefer task indexes over encyclopedias
  • Graduate up the ladder; delete lower copy
  • Point rules at one exemplar file to copy
  • Capture Chase-isms once, then reuse
  • Run check-docs.js when adding/moving docs

Don’t

  • Add always-on rules for app-specific stuff
  • Map every button on Pearson (task recipes only)
  • Duplicate AGENTS.md prose in app rules
  • Assume chat memory persists
  • Create a new hook without grepping first

Consistent workflow for you
