Supabase setup — student progress tracking

Six steps, all in your browser. The only real typing is a project name.

One-off scratch page · written 2026-09-04 · will go stale

1 Sign in and see if you already have a project

If you signed up before, any projects you made will be listed on the dashboard after you sign in. If the list is empty, you have an account but no project — that's fine, step 2 makes one.

Open the Supabase dashboard →

Sign in with whichever method you used originally — GitHub is the most common. If nothing works, just sign up fresh; the free tier is plenty for this.

2 Create the project

Click New project. Four things to fill in:

  • Name — type student-progress
  • Database Password — click the Generate a password link so you don't have to type one. Save it somewhere, but you will almost certainly never need it — the apps authenticate with API keys, not this password.
  • Region — pick the closest US one (East US or Central US)
  • Plan — Free

Then click Create new project.

Expect: a progress spinner for roughly two minutes while it builds the database. You can leave the tab and come back.

3 Copy the setup SQL

This creates the tables that hold practice attempts. It's already written and sitting in your repo — this button just puts it on your clipboard so you don't have to select it by hand.

Source: School Scrips\student-session-kit\supabase\migrations\001_initial.sql

4 Paste it into the SQL editor and run it

  • In your new project, click SQL Editor in the left sidebar
  • Click New query
  • Click in the big empty text area and paste (Ctrl+V)
  • Click the green Run button at the bottom right
Expect: a green message reading “Success. No rows returned”. That's what success looks like — it created tables rather than fetching anything, so there's nothing to show.

5 Find the two values I need

In the left sidebar go to Project Settings (the gear at the bottom), then API. Two things on that page:

  • Project URL — looks like https://abcdefgh.supabase.co
  • anon public key — a very long string of characters starting with eyJ

Each has a copy icon next to it, so no selecting by hand.

Both of these are safe to paste to me in chat. The anon key is designed to be public — it ships inside the JavaScript that every student's browser downloads. The database is locked down so that key can only add practice results, never read anything.
Do not paste the service_role key to me. That one is on the same page and it bypasses every security rule. You don't need it yet at all — it's only for the teacher-side reader in Macro App, which has nothing to read until students start using the apps. We'll set it up later, and it goes straight into a file that is already gitignored, never into a chat message.

6 Send me the Project URL and the anon key

Paste them both into chat and I'll wire up the rest: the student code system, the link generator that produces one link per student for you to email, and the Netlify environment variable.

What you'll have when this is done

A database in the cloud that can record “code 7F3K9Q practiced Transformations and scored 8 of 10” — and which contains no student name, no email, and no way to identify anybody. The only thing on earth that connects a code to a real student is a file on your own PC.
