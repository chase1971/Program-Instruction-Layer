Teacher Console — five interface concepts

All five assume the same sidebar vocabulary: Dashboard / Exit Tickets / Apps / Reports / Announcements / Settings. No messaging, no notes, no bookmarks, no upgrade CTA. What differs is what the home screen is and where the course lives.

A — Course-first console

Course pills pinned across the top; everything below belongs to the selected class. Home shows the live app tiles for that class with per-tile toggles, plus recent exit tickets and a class snapshot.

Strength: you can never act on the wrong class by accident — the course is always visible. Closest to how you already work with course tabs. Weakness: nothing is comparable across classes; to see what MATH 2412 has you have to switch.

B — Task-first console

Home is four oversized action cards: Create Exit Ticket, Assign Apps, Post Announcement, View Results. Course gets chosen inside whichever task you pick.

Strength: biggest possible click targets and zero learning curve — you never wonder where anything is. Weakness: it's a menu, not a dashboard. You get no information at a glance, and every task is one extra click deep.

C — Split builder

The authoring screen itself. Paste from AI on the left with a "Copy AI Prompt" button beside it, parsed questions listed beneath with the correct answer highlighted, live student preview on the right, and an assign-to-class row with Publish along the bottom.

Strength: this is the actual feature you said you'd use every day, and preview-before-publish is built into the layout rather than bolted on. Paste → check → assign is one screen. Weakness: it's one screen, not a whole console — it belongs inside A, D, or E rather than replacing them.

D — Assignment matrix

Apps and exit tickets as rows, your four courses as columns, one big toggle per cell. Publish changes in the corner.

Strength: solves "not all classes get the same apps" better than anything else here — the whole assignment state is one glance, and mistakes are visible instead of hidden behind a tab. Weakness: only answers one question. It's a great Apps screen, not a great home screen.

E — Live portal mirror

Home is a mirror of the real student portal for the selected course, with an edit rail beside it: eye icons to hide, arrows to reorder, "Add exit ticket", and an announcement box underneath.

Strength: directly answers "it would be nice to actually view the app here." You edit in terms of what students see, so hiding something is unambiguous. Weakness: the most work to build, and the mirror has to stay honest or it becomes a lie you trust.

These aren't really five rivals

B is a front door, and C and D are individual screens. Only A and E are competing answers to "what is the home screen."

The combination that seems to fit what you described:

  • E as the Dashboard — the live mirror, so you always see the current state of the app
  • C as the Exit Tickets screen — paste, preview, assign, publish
  • D as the Apps screen — the class-by-app toggle grid
  • A's course pills as a persistent top bar everywhere except D, which is already all-courses
  • Reports and Announcements as their own screens; today's roster and grades tables move under Reports
