The experiment queue — ranked

Each of these changes one thing, then re-runs the same 20 questions. One change per run, or you won't know which one caused the difference.

1

Consolidate the Python launcher docs

Your worst lookup by a wide margin: 133k tokens, 6.9× the floor. The answer is scattered across the AGENTS.md launcher table, an exemplar .vbs, and two separate docs. Put the whole answer in one place and point everything else at it.

node scripts/run-probes.js --label "launcher-docs-consolidated"

Watch: does python-launcher drop from 133k toward the 19k floor?

2

Is the expensive model worth it?

The question you actually wanted answered. Same 20 questions, different model, so difficulty is held constant. This is the only fair version of that comparison — and it costs 5 minutes instead of the big experiment I talked you out of.

node scripts/run-probes.js --label "opus" --model claude-opus-5-thinking-high

Watch: does correctness rise at all? If it stays 20/20, the cheap model is already sufficient for retrieval and you should keep using auto.

3

Add harder questions

Everything passed. That's good news about your docs, but it means correctness has nowhere to move — right now only token cost can improve. Add 8–10 questions that span two or three docs, or that have a subtle right answer.

Rule: append new ones with new ids. Never reword an existing question — that silently invalidates every earlier run.

4

Try shortening AGENTS.md

The always-on tier averages 29.5k per question. If a shorter AGENTS.md keeps 6/6 correct at lower cost, that's a free win. If correctness drops, you've found the floor and should put the text back — which is worth knowing either way.

Watch the always-on tier specifically. The routed tier shouldn't move much.

5

Restructure the four-branch table in INDEX.md

14 of the 20 questions are routing questions averaging 49.3k each — 1.7× the always-on tier. That gap is the price of navigation, and INDEX.md is the thing standing in the middle of it.

Watch the routed tier average. Anything under 45k is a real improvement.

Settled facts — don't re-derive these

Measured 2026-09-08 from 36 Claude Code sessions and Cursor's local database.

FindingNumberWhat it means
Reading vs writing 34% vs 8.5% Reading files costs 4.1× what editing them costs. Time on screen tracks output tokens, which are a thin slice of the bill.
Long-session penalty 8.1× A turn in a 600+ turn session costs 8× a turn in a short one. Superlinear — every turn re-reads everything before it.
Always-on doc cost 1.2% AGENTS.md + CLAUDE.md + MEMORY.md are 1.2% of billed tokens. Trimming them is a quality lever, not a cost one.
Indexing still matters via Read Bad routing causes extra file reads, and Read is the largest cost line. The index is a cost lever — through what it prevents, not its own size.
Cursor model attribution 98% blank Cursor records tokens locally but omits modelName on 98% of requests. No passive answer to the model question exists — it needs the probe set.
Navigation premium 1.7× Routed questions cost 49.3k vs 29.5k for always-on. That gap is what your index is fighting.

The single biggest lever, if you only do one thing

Start new chats more often. Not because the model forgets — it doesn't anymore, which is exactly the problem. The symptom that used to tell you to start fresh is gone, but the cost didn't go away. It just got quiet.

A new chat at a natural task boundary saves more than any doc change on this page.

Rules that keep the data honest

Never edit an existing probe question. Comparability is the entire point. Append new ones with new ids instead.

One change per run. Two changes in one delta can't be told apart.

Only compare runs on the same model. Otherwise you're measuring the model, not the docs.

Grading is keyword matching, so it's approximate. Before believing a surprising FAIL, open the run JSON in agent docs/probes/runs/ and read what the agent actually said.
