Two kinds of guidance — never mix them

Always-on rule

Fires whether or not you asked

  • File size cap — 800 lines
  • App.tsx is an orchestrator
  • Modal sizing
  • Never put anything on screen without asking
  • PowerShell 5.1 — no &&
  • Pull at start, push at end

Look-up

Only when the topic comes up

  • How to build a dwell-drag
  • Pearson browser automation
  • The scorecard procedure
  • Grade sync recovery
  • Packaging an installer
  • FERPA handling

A rule you need every session must never be an index row — routing it would make it optional. A doc you need occasionally must never be always-on — it would cost tokens every session forever.

The one rule that keeps it clean

The index names owners.
Owners name their contents.
Never reach past an owner.

Same rule as App.tsx. The index says "building an interaction → recipes" — it never lists an individual recipe. So adding a recipe never touches the index, and the index only changes when a whole new category appears.

Make it unable to rot
  1. Route the ~17 loose instruction docs

  3. Add the length monitor
C · Prune the branches
One branch at a time
  1. cursor-patterns — 1244-line file down to ~430, fix the wrong numbers
  2. recipes — prune, then re-split the categories
  3. apps — the missing keyword tables
  4. Delete the old routers, after a week

The trunk has to work before anything gets pruned — a bad trunk means pruning the wrong branches. Expect a lot of deletions in Stage C.
