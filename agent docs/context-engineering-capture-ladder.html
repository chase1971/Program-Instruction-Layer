Capture Ladder — Scenarios

When something should stick, agents push knowledge up the ladder and delete weaker copies. Real examples from your Programs setup.

The five rungs (strongest first)

1Structurally impossible — one owner, API that can't be misused
2Lint or test — violation fails CI / pre-commit
3Glob .mdc — fires when matching files are open (default for UI/code patterns)
4Always-on rule — every session; ~200-line budget total
5On-demand doc / exemplar — task recipes, HTML templates, deep dives

Capture flow (when you say a trigger phrase)

Triggers: “capture that”, “remember:”, “make sure you always/never…”, “that was the third time” / “again” (forces graduate up one rung)

Runs .claude/skills/capture/SKILL.md — you don't pick the file or rung.

You say one sentence → Agent greps — already exists? → Pick highest rung that fits → Write rule/doc/code → Delete lower duplicate → Index in CLAUDE.md / AGENTS.md

Quick decision — which rung?

  1. One-off task? (“fix this typo”) → don't capture
  2. Only one app / file type? → Rung 3 glob .mdc (or Rung 5 task doc if it's a procedure)
  3. Every session, every app, short? → Rung 4 always-on (sparingly)
  4. Machine can detect violations? → Rung 2 lint/test
  5. About who owns a mechanism? → Rung 1 code shape
  6. Visual layout you'll repeat a few times? → Rung 5 exemplar HTML — not a new always-on rule yet
  7. Said it three times and agents still miss? → Graduate up one rung

Scenario walkthroughs

Only one module may touch localStorage

Rung 1

What happened

Three different hooks were writing localStorage keys — prefs got overwritten unpredictably.

Capture choice

Route all persistence through usePersistedState.ts — other files literally can't import a second path without it being obvious.

Why not rung 5?

A doc saying “use usePersistedState” still gets ignored. Ownership in code is the fix.

800-line file cap keeps getting violated

Rung 2

What happened

Agents add to already-huge files because nothing stops them at commit time.

Capture choice

scripts/check-file-size.js + pre-commit hook + glob rule 10-file-size-before-edit.mdc pointing at it.

Graduate path

If agents bypass hook → make CI fail too. Doc-only reminder stays deleted once lint owns it.

Clickable HTML links in chat — never C:\... paths

Rung 3 + 5

Rung 4

Capture choice

“What's in homework 3.4?” — data vs procedure

Rung 5

Two files, two jobs

Procedure: PEARSON_BROWSER_AUTOMATION.md — how to harvest.
Data: PEARSON_QUESTION_INVENTORY.md — question IDs snapshot.

Flow

“What's in 3.4?” → Read inventory (data) → Done — no browser
“List IDs fresh” → Read recipe (procedure) → Run script → Update inventory

When NOT to capture

Don't capture

  • One-off typo or single-session tweak
  • “Use blue for this button” (unless it's a design system rule)
  • Anything already in code/git history
  • Vague preference with no failure mode
  • Task-specific rule you'll delete when course ends

Verbose still works (no keyword)

“As you figure out Pearson, write it in the proper doc before we end.”

Same outcome as “capture that in the Pearson doc” — workflow instruction for this session + doc update. Capture skill is the failsafe when it must become durable infrastructure.

Rule bloat — what actually costs you

Costs every session

  • alwaysApply: true rules
  • AGENTS.md (large baseline)
  • Duplicate prose in 3 places

Cheap until needed

  • 1000 glob .mdc files on disk
  • Exemplar HTML files
  • Task docs + inventories
  • Rules with narrow globs

Agents don't scan all .mdc files every turn — Cursor injects always-on + matching globs. Bloat = too many always-on + overlapping globs + no exemplar to grep toward.
